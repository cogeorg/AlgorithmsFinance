IMPLEMENTED PRODUCTION INTERFACES
The existing scalar interface in american_put.py is unchanged:
  price_american_put(S0, K, u, d, R, N) -> float

New companion in exercise_policy.py, using the SAME six inputs/validation:
  price_american_put_with_boundary(S0, K, u, d, R, N) -> PutExerciseResult
    price: same scalar time-zero value
    boundary: tuple of N+1 values, indexed by t=0,...,N

  first_observed_exercise(prices, boundary, K, *, timestamps_utc) -> ObservedExercise
    kind: 'early_exercise', 'maturity_settlement', or 'never'
    index: the actual observation index, or None for 'never'
    timestamp_utc: that observation's supplied UTC timestamp, or None
    payoff: K-P_t on exercise/positive settlement; zero for 'never'

Both functions, scalar pricing and calibration are implemented. Scalar and
boundary pricing share a one-row engine, with O(N^2) time and O(N) memory. market_test_support.py is only input-checking
and wiring for tests/benchmarks; it never supplies option values or boundaries.

BOUNDARY AND TIE CONVENTIONS
- boundary[t] is the HIGHEST stock price among exercise-classified tree nodes
  at t. Missing exercise region: None, never zero, NaN, or a missing list entry.
- Include time-zero root and maturity. For N=0 the only entry is maturity at 0.
- Before maturity: exercise if intrinsic > continuation, strictly. Exact ties
  continue, including positive-value ties and intrinsic=continuation=0.
- At maturity: positive intrinsic nodes settle; zero-payoff nodes are not
  exercise nodes. Every numeric boundary is therefore positive and below K.
- Value comparisons in tests allow floating-point rounding (1e-12 relative
  and absolute). Node-decision ties use the stated strict rule; no volatility
  floor or arbitrary fuzzy exercise margin is introduced.
- On the OBSERVED path, equality P_t=boundary[t] qualifies. A boundary names
  an exercising node. This comparison is separate from the value tie rule.

INDEPENDENT, EXACT TREE CHECKS
The test-only exact_full_tree_decisions in test_exercise_policy.py expands both
children using fractions.Fraction, records intrinsic/continuation/classification
for every full-tree path node, and finds each date's maximum exercising price.
It calls no production helpers. Separate self-checks anchor it to hand-worked
numbers, so reference errors can be reported before production exists.

  t=2: exercising stock prices are 64 and 96; the maximum is 96.

  Root intrinsic=continuation=20 -> continue; boundary (None,90).

  All payoffs zero -> boundary (None,None).

OBSERVED-PATH CONVENTIONS
- Scan t=0,...,N-1 for the first non-None boundary reached from above or touched
  (P_t<=boundary[t]) with positive payoff. Report the first date, not the
  largest later payoff. Time-zero early exercise is possible if N>0.
- If there is no early exercise and K-P_N>0, report maturity_settlement at N.
  Settlement uses the observed expiry price even if it is off the tree lattice
  and above boundary[N]; the terminal contractual payoff still applies.
- If no early exercise and the expiry payoff is zero, report kind='never',
  index/timestamp None and payoff 0. This explicitly represents "Never".
- At immediate expiry N=0, positive payoff is maturity settlement, not early
  exercise. A zero payoff gives 'never'.
- Require aligned, nonempty date axes and UTC-aware increasing timestamps.
  Reject invalid lengths, invalid timestamps and zero/NaN missing-region markers.

PREPARED BITCOIN CHECKS (FAST)
Tests read output/window_summary.csv, falling back to results/window_summary.csv,
and the existing two Bitcoin window files under output/windows/.
The one-year file must have 8,761 closes, N=8,760 and P_0...P_8760 labels.
S0=K is checked against the FIRST selected close and the raw file's last 8,761
closes. It is not the latest close. Actual elapsed hours must equal 8,760.
The test/benchmark gate uses ACT/365F elapsed years, making T=1 here.

The full-history file retains a two-hour jump over 2023-03-24T13:00:00Z.
Tests require the preparation flag and prove calibration is never called on
that window. The actual timestamps are checked too, so merely changing a
metadata flag cannot hide the gap. No hours are filled or dropped.

OPTIONAL MARKET PRICING CHECK (EXPENSIVE; NOT DEFAULT)
After calibration and boundary pricing are implemented, explicitly run:
  python bitcoin_integration_check.py --run
It checks a finite Bitcoin price, calibration length N, boundary length N+1,
date-axis alignment, and valid boundary entries. There is NO invented expected
market-data option price and no pass/fail runtime threshold.
If implementation is missing, it reports an explicit pending-implementation
failure. Without --run it refuses to run; importing it through unittest without
opt-in skips the expensive case before loading data or calling calibration.
The filename does not match test*.py and run_tests.py excludes the module.
