What changed, and why?

  • Linear: stop at the first match and read the original IDs without copying. Absent queries still scan the entire input.
  • Binary: use an iterative manual search and remove the extra copy before sorting. Sorting still creates a separate ordered list.
  • Set: build the set directly from IDs and collect membership answers with a list comprehension. Fast lookups require an allocated hash table.

A revision is not guaranteed to win every small measurement. Compare both timing and memory, including preparation. See the revision notes and the measured findings.

Limits of this experiment
One seed on one machine. Versions are measured sequentially, so machine load, cache warmth, and allocator state can affect comparisons. Query-only measurements reuse prepared state within a timed batch; each repeat gets fresh preparation. No confidence intervals are claimed. Tracemalloc does not capture every native allocation. With one query, “mixed” contains one present query.
