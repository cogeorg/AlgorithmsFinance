Diagnostic operation counts

Measured bottleneck and code complexity. Version A duplicate checks, cancellation, maker filtering, and exhausted-order cleanup each scan up to B active orders: O(B) per scan. Eligible makers are additionally sorted in O(K log K). As passive buildup makes B grow with M, repeated scans sum to quadratic-like O(M²) work; the diagnostic estimate reaches 49,995,000 comparisons/scanned entries per category at 10,000 events. Version B uses expected O(1) dictionary lookup by ID and price plus expected O(1) FIFO insertion/removal inside an OrderedDict level. New-level insertion and each stale-top pop cost O(log H), where H is the actual heap length—not simply P. The implementation can rebuild a heap in O(P) when H > 2P + 64, so heap maintenance is best described with explicit rebuild cost and amortized cleanup, not unconditional O(log P). Under cancellation churn, B stays near one, making Version A scans cheap, while Version B pays dictionary, queue, stale-entry, and periodic heap-rebuild overhead.

Version A scan counts are analytical estimates from pre-event state. Version B wrapper calls and heap changes are directly observed where labelled. Diagnostic time is instrumented and is never treated as primary timing.
